# spanscope offline viewer

This is the source of the one-file HTML report packaged by `cargo-spanscope`
and the optional `spanscope/viewer` runtime feature. React 19, strict
TypeScript, Vite 7, Tailwind 4, Radix Dialog, Zustand, TanStack Table/Virtual,
and ECharts build an offline overview, routine/caller breakdown, run-level
composition and individual-call explorer, metric comparison, interactive call
graph, structural flame graph, virtualized call chains table, raw explorer,
command palette, themes, and hash-linked filters.
The parser and schema-v1 validator run in a Blob-backed worker. The report
accepts embedded JSON or local JSON/gzip files selected or dropped by the user.
It does not fetch a sidecar automatically from `file://`.

```sh
npm ci
npm run build          # builds and copies identical viewer.html into both crates
npm run verify:asset   # checks generated copies are current
npm test                # Vitest parser/index/filter tests
cargo build -p cargo-spanscope
npm run test:e2e        # Playwright Chromium over file://, HTTP blocked
```

`src/generated/profile.d.ts` derives from `schema/profile-v1.schema.json` during
the build. `scripts/inline.mjs` embeds all built JS/CSS in one HTML file. The
checked-in asset is about 1.10 MB, below the 3 MB target, and consumer Cargo
builds do not invoke Node. `viewer/fixtures/example.json` is generated by
`spanscope/examples/export_profile.rs`, not a hand-written mock.

The flame graph is a structural aggregate using active self time, not an
execution timeline or a measured parallel critical path. Large-file parsing
and causal analysis are not yet implemented. The current worker
validates the complete JSON Schema but still materializes the complete input
and index in memory; capacity beyond the 50 MiB inline threshold has not yet
been measured. Exact JSON integers are converted to `BigInt` before indexing;
visual coordinates may use floating-point approximations.

The libraries that end up in the bundle are resolved from the production build
sourcemaps and listed in `scripts/bundled-packages.json`; `npm run notices`
regenerates `THIRD-PARTY-NOTICES.md` from their license files, including the
Apache-2.0 NOTICE that ECharts ships. `scripts/inline.mjs` embeds that text as a
comment at the top of the single-file report, so the attributions travel with
every copy of it. MPL-2.0 and CC-BY-4.0 packages appear only in build tooling
(lightningcss, caniuse-lite) and contribute no code to the bundle.
